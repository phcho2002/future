# 假突破系统 → 多周期(60m定关键位 + 15m找形态)改造计划

## 设计概要

**核心思路**:60m 定趋势+关键价位(密集区+swing点),价格接近关键位(1 ATR内)后,在 15m 上找入场形态(阳吞阴/阴吞阳 或 5根合并K实体方向)。

**不破坏现有代码**:所有新逻辑放新模块,`generate_signal`(单周期假突破)原样保留。多周期走新的 `generate_mtf_signal` 入口。`backtester.py` 不动,新增 `mtf_backtester.py`。

## 信号流程

```
60m K线 → add_indicators(60m)
       → detect_trend(60m swing)          ← 复用 trend.py,判断 long/short_eligible
       → detect_volume_zones(60m)          ← 复用 levels.py,成交密集区
       → detect_swing_zones(60m)           ← 新,swing高/低点包装成Zone
       → 合并两类zone,按趋势方向筛选(做多取下方支撑/做空取上方阻力)
       → zones_near_price(距当前15m收盘价 1 ATR内)  ← 接近判定
                        ↓ 命中关键zone
15m K线 → detect_engulfing(最近2根)        ← 新,阳吞阴/阴吞阳
       → detect_merged_body(最近5根)       ← 新,合并K实体方向
       → 满足任一 → 出 Signal(entry/stop/target)
```

入场/止损/目标位:
- **入场**:形态确认那根 15m 的收盘价
- **止损**:关键 zone 的另一侧(zone.lower 做多 / zone.upper 做空),复用现有思路
- **目标**:复用 `_upside_target`/`_downside_target`(ATR目标与下一zone中心取保守值)

### 7. `scan_mtf_60m_15m.py` (新) — 扫描入口
仿 `scan_tbpy_60m.py` 结构,用 `tbpy_provider.get_klines_batch` 同时拉 60m + 15m 两套,调 `generate_mtf_signal`,输出 CSV。

### 8. `backtest/mtf_backtester.py` (新) — 多周期回测器
**15m 为主时间轴**。关键设计:
- 输入:15m DataFrame(主序列)
- 内部从 15m 聚合出 60m(按 datetime 向下取整到小时 groupby,天然处理午休/夜盘)
- 逐 15m 推进,维护 60m 索引指针:当前 15m 落入新 60m 桶时刷新 60m zone/趋势缓存
- 仓位管理逻辑(开仓/加仓/止损/止盈)从 `backtester.py` 复用模式,信号调用换 `generate_mtf_signal`
- 复用 `BacktestConfig`/`Trade`/`BacktestResult` 数据类

### 9. `config.yaml` — 加 `mtf:` 参数段(对应新config字段)

## 不动的文件
- `signal.py`(单周期假突破)、`trend.py`、`levels.py`、`swing.py`、`indicators.py`、`backtester.py`、现有扫描脚本 —— 全部原样保留

## 实施顺序
1. types.py 扩展 → patterns.py → htf_zones.py(纯函数,可独立测)
2. config.py 扩展 → mtf_signal.py(组装)
3. scan_mtf_60m_15m.py(先验证能出信号)
4. mtf_backtester.py(回测验证)
5. config.yaml 补参数

## 验证方式
- 先跑 scan_mtf_60m_15m.py 对 PP0/IM0 等 T1 品种,确认能出合理信号(entry/stop/target 方向对、zone 接近判定生效)
- 再跑 mtf 回测对比单周期假突破的 PF/盈亏比
