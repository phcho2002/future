# 全面数据源改造方案：tqsdk/tbpy → xtquant(token模式)

## 总体策略

以 `future_data/` 中心化包为核心，新增 `xtquant_provider.py` 作为主数据源后端，保留 `akshare_provider.py` 作为备份。所有 `future_N` 子系统和顶层脚本通过统一入口自动受益。

**后端优先级**：`xtquant`（主） → `akshare`（备）。完全移除 `tqsdk`、`tbpy`、`bigquant`。

## 阶段一：核心数据层（future_data 包）

### 1.1 新建 `xt_token.py`（凭证文件）
类似现有 `tq_auth.py`，存储迅投 token：
```python
# 迅投投研 token（用于 xtquant token 模式连接）
XT_TOKEN = "5952ec3a269f0fe028c4a74209833122b8ed0221"
```

### 1.2 新建 `future_data/xtquant_provider.py`（核心模块）
实现：
- **token 初始化**：`xtdatacenter.set_token()` + `xtdatacenter.init()`，进程内幂等（`@lru_cache`），token 读取顺序：环境变量 `XT_TOKEN` → `xt_token.py` 文件
- **符号映射**：`(symbol, exchange)` → 迅投代码（如 `RB0`+`SHFE` → `rb00.SF`），支持主力连续(`品种00.后缀`)和具体月份合约(`品种YYMM.后缀`)
- **period 映射**：系统内部用分钟数字(`"15"`/`"60"`/`"1440"`)，转换为迅投周期(`"15m"`/`"1h"`/`"1d"`)
- **数据获取流程**：`download_history_data2()` 下载 → `get_market_data_ex(count=length)` 读取
- **规范化**：迅投返回的 `time`(毫秒int) → `pd.Timestamp`，提取 `[datetime, open, high, low, close, volume]`，升序排列
- **核心函数**：
  ```python
  fetch_kline_xtquant(symbol, exchange, period="15", length=200) -> DataFrame
  fetch_many_xtquant(symbols: list[tuple], period="15", length=200) -> dict[str, DataFrame]
  normalize_xtquant(raw: DataFrame) -> DataFrame  # 迅投原始 → 标准 schema
  ```

## 技术要点

### period 映射表
| 系统内部 | 迅投 period |
|---|---|
| "1" | "1m" |
| "5" | "5m" |
| "15" | "15m" |
| "30" | "30m" |
| "60" | "1h" |
| "1440"/"D"/"1d" | "1d" |

### 迅投连接代码模式
```python
from xtquant import xtdatacenter as xtdc
from xtquant import xt_data as xtdata

# 进程级初始化（一次）
xtdc.set_token(token)
xtdc.init()  # ~10秒

# 拉数据（可反复调用）
xtdata.download_history_data2([symbol], period, start_time, end_time)
data = xtdata.get_market_data_ex([], [symbol], period=period, count=length)
df = data[symbol]  # DataFrame
```

### 规范化：迅投 → 系统 schema
```python
# 迅投 time 列是毫秒int（如 1692288000000）
df["datetime"] = pd.to_datetime(df["time"], unit="ms")
# 提取 [datetime, open, high, low, close, volume]，升序
```
