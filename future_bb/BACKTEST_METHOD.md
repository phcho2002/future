# 二次突破系统 回测方法说明 (BACKTEST_METHOD.md)

> 本文件固化 future_bb 二次突破(假突破→真突破)系统的回测方法,便于后续复用、调参与品种池调整。
> 策略代码:`backtest_30m.py` | 形态检测:`indicators.py` | 策略参数:`config.py` | 品种池/资金:`strategy_config.yaml`

---

## 一、策略逻辑:四阶段状态机

入场采用「蓄势 → 首次假突破 → 失败回踩 → 二次真突破」四阶段状态机(做多为例,做空完全对称):

```
阶段1 蓄势(IDLE→PRIMED): 近 N 根处于 箱体 或 收敛楔形
  ├─ 箱体:   (最高-最低)/最低 ≤ BOX_RANGE_MAX(2%)
  │          且 上边界触碰 ≥ BOX_TOUCH_MIN(2) 且 下边界触碰 ≥ 2
  └─ 收敛楔形: 近N根ATR < 前N根ATR × 0.8(波动收敛)
              且 后半段波幅 < 前半段波幅 × 0.8(波幅收窄)
  (任一成立即可,记录此时的阻力位/支撑位)

阶段2 首次突破(PRIMED→BROKEN): 收盘价突破形态边界(阻力/支撑)
                                ← 第一次,可能失败

阶段3 失败确认(BROKEN→FAILED):  收盘价回到形态边界内,持续 ≥ FAIL_CONFIRM_BARS(2)根
                                ← 关键!验证首次突破失败

阶段4 二次突破(FAILED→入场):    收盘价再次突破边界 + EMA200顺势(价在EMA200上做多/下做空)
                                ← 这才是入场信号
```

**超时回退**:首次突破后超过 `SECOND_BREAK_MAX_GAP`(20根)未发生二次突破,状态机回到 IDLE 重新开始。

### 关键参数(config.py)

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `PATTERN_LOOKBACK` | 20 | 蓄势形态回看窗口(K线根数) |
| `BOX_RANGE_MAX` | 0.02 | 箱体最大波幅(2%) |
| `BOX_TOUCH_MIN` | 2 | 箱体边界最小触碰次数 |
| `WEDGE_ATR_SHRINK` | 0.8 | 楔形:近期ATR/前期ATR上限 |
| `BREAKOUT_THRESHOLD_2ND` | 0.003 | 二次突破价格阈值(0.3%) |
| `FAIL_CONFIRM_BARS` | 2 | 失败确认需持续的根数 |
| `SECOND_BREAK_MAX_GAP` | 20 | 首次→二次突破最大间隔(超时作废) |
| `EMA_PERIOD` | 200 | EMA顺势过滤周期 |

## 二、资金管理与出场

> **出场策略核心:让利润奔跑**(实测6品种小时线 账户收益率 +8.45% / 胜率 44.7% / 盈亏比 4.0)
> 突破系统的利润来自少数大趋势单,核心是"拿住盈利单",故采用纯移动止损、不用固定R止盈。

### 开仓
- **信号在K线 `i` 收盘确认,`i+1` 开盘价开仓**(优化版无滑点)
- **开仓手数** = 当前资金 × `risk_capital_ratio`(8%) ÷ (入场价 × 合约乘数 × 保证金率)
- 每品种独立账户,初始资金 `initial_capital`(500万)

### 加仓
- **触发条件**:价格顺向相对上次加仓价走 `add_atr_step`(2.0)× ATR → 加仓(可多次,非一次性)
- **加仓手数** = 当前资金 × `add_capital_ratio`(3%) ÷ (现价 × 合约乘数 × 保证金率)
- 加仓后更新"上次加仓价"为当前价,作为下一次加仓的基准

### 出场(优先级从高到低)
1. **移动止损**(主出场,全程启用):跟踪近期极值 ∓ `trail_atr_mult`(2.0)×ATR
   - 做多:止损 = max(历史止损, 当根低点 − 2.0×ATR),只上移
   - 做空:止损 = min(历史止损, 当根高点 + 2.0×ATR),只下移
   - 价格触及移动止损 → 全平
2. **灾难止损**(兜底):单笔浮亏达开仓时总资金 × `hard_stop_loss`(3%)→ 立即全平
   - 不频繁干扰,只在极端情况兜底
3. **未创新极值止盈**(可选,默认禁用):连续 `no_new_extreme_bars` 根未创新极值 → 全平
   - 优化版设为 0(禁用),纯靠移动止损让趋势单充分运行

> **设计对比**:旧规则(0.9%紧硬止损 + 3根止盈 + 1.2ATR紧移动止损)会把大盈利单截断,均持仓仅7根、账户收益率+1.43%;优化后(3%灾难止损 + 纯移动止损2.0ATR)均持仓延长到20根、账户收益率+8.45%。

### 关键参数(strategy_config.yaml)

**资金管理(money_management)**

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `risk_capital_ratio` | 0.08 | 开仓用当前资金 8% 作保证金 |
| `add_capital_ratio` | 0.03 | 加仓每次用当前资金 3% |
| `add_atr_step` | 2.0 | 加仓触发:顺向走 2×ATR |
| `hard_stop_loss` | 0.03 | 灾难止损 3%(总资金) |
| `margin_rate` | 0.12 | 保证金率(手数换算用) |

**出场策略(exit_strategy)**

| 参数 | 默认值 | 含义 |
|------|--------|------|
| `initial_stop_atr` | 1.5 | 初始止损 = 突破位 ∓ 1.5×ATR |
| `trail_atr_mult` | 2.0 | 移动止损跟踪极值 ∓ 2.0×ATR |
| `no_new_extreme_bars` | 0 | 未创新极值止盈根数(0=禁用) |
| `lookback` | 20 | 前 N 根高/低点(创新极值判定窗口) |

## 三、回测执行流程

### 快速运行

```bash
cd D:/work_ai/future_bb
python backtest_30m.py
```

首次运行联网拉数据(约1-2分钟,品种多时用 `fetch_many` 批量),后续走 `quote_cache/` 缓存纯读盘(秒级)。

### 数据流

1. **读配置**:`backtest_30m.py` 启动时从 `strategy_config.yaml` 加载品种池/资金/参数(无yaml则用代码默认值)
2. **拉数据**:每个品种调 `future_data.get_klines(symbol, exchange, period, length)` 获取K线,落盘 `D:/work_ai/quote_cache/{symbol}_{period}m.parquet`
3. **状态机**:对每个品种的K线跑 `SecondBreakoutEngine.run()`,产出二次突破入场信号 `[(idx, side, level, atr), ...]`
4. **逐K线回测**:`backtest_symbol()` 按时间顺序处理每根K线——持仓中检查出场、无持仓检查入场信号
5. **统计输出**:控制台打印汇总表 + 导出 CSV 到 `output/`

### 输出

- **控制台**:多品种汇总表(信号数/胜率/账户收益率/年化/盈亏比/加仓率/均持仓)
- **CSV**:`output/backtest_30m_summary.csv`(每品种一行汇总)、`output/backtest_30m_trades.csv`(逐笔记录)

## 四、指标定义

| 指标 | 计算方式 |
|------|---------|
| **信号数** | 状态机产出的二次突破信号总数(含因单仓限制未开仓的重叠信号) |
| **交易数** | 实际开仓平仓的笔数 |
| **胜率** | 盈利交易数(pnl_money>0) ÷ 总交易数 |
| **账户收益率** | 总盈亏金额 ÷ 初始资金(500万/品种)——含加仓放大效应 |
| **年化收益率** | (1+账户收益率)^(365/实际天数) − 1,实际天数=末根−首根K线的天数 |
| **盈亏比** | 平均盈利金额 ÷ 平均亏损金额 |
| **加仓率** | 触发加仓的交易占比(浮盈达1R) |
| **均持仓** | 单笔交易平均持仓K线根数 |

## 五、复用场景

### 场景1:换品种池
编辑 `strategy_config.yaml` 的 `universe` 段,改品种列表后重跑即可。
```yaml
universe:
  - {symbol: "SN0", name: "锡", exchange: "shfe", multiplier: 1}
  - ... # 增减品种
```

### 场景2:换周期(30分钟 ↔ 小时)
改 `strategy_config.yaml` 的 `backtest.kline_period`:
```yaml
backtest:
  kline_period: "60"   # "30"=30分钟, "60"=小时级别
```

### 场景3:调资金管理
改 `strategy_config.yaml` 的 `money_management` 段(开仓比例/加仓比例/硬止损)。

### 场景4:调策略参数(蓄势/突破/止损)
改 `config.py` 里对应的 `PATTERN_LOOKBACK`/`FAIL_CONFIRM_BARS`/`EXIT_*_ATR` 等。

### 场景5:按月调仓
每月初用过去60交易日数据跑全候选品种回测,按 `strategy_config.yaml → rebalance` 的门槛调整品种池,记录到 `rebalance.history`。移除门槛:胜率<25%且盈亏比<1.0 或 单月回撤>5%;纳入门槛:胜率>40%且盈亏比>1.5且信号≥8笔。

## 七、经验要点(实测得出)

1. **小时级别优于30分钟**:同品种小时线胜率和收益都显著更高(蓄势形态更可靠、假突破更少)。30分钟噪声大,胜率普遍下降10-15个百分点。默认推荐小时级别。
2. **二次突破质量分化大**:高波动趋势品种(SN0锡/LC0碳酸锂)二次突破质量极高(胜率>70%或盈亏比>6);震荡品种(TA0/MA0/CU0)即使二次突破仍频繁假突破,应剔除。
3. **EMA200是微正向过滤器**:对趋势性强的品种提升胜率(SN0从68%→75%),但对整体影响在噪声范围内,可酌情开关。
4. **让利润奔跑是核心**:突破系统利润来自少数大趋势单。实测对比——紧规则(0.9%硬止损+3根止盈+1.2ATR移动止损)账户收益率仅+1.43%、均持仓7根;放宽后(3%灾难止损+纯移动止损2.0ATR+2ATR加仓)**账户收益率+8.45%、均持仓20根、盈亏比4.0**。关键:不用固定R止盈截断利润,移动止损给足呼吸空间(2.0ATR)。
5. **样本量是关键**:二次突破信号稀疏(每品种十几个/数年),单品种统计意义有限,**组合多品种 + 长周期数据**才能得到可靠结论。
6. **当前最优配置(6品种小时线)**:SN0/LC0/P0/AO0/CF0/AU0,二次突破入场 + 让利润奔跑出场,实测账户收益率+8.45%(LC0+28%/SN0+18%/AO0+7.6% 三强驱动)。
